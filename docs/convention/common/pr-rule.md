# PR(Pull Request) 규칙

## 제목 형식

```
[<type>] <작업 내용 요약>
예: [Feat] 로그인 페이지 UI 구현
```

## PR 템플릿

```markdown
## 작업 내용
- 무엇을 했는지 요약

## 스크린샷 (UI 변경 시 필수)
| Before | After |
|---|---|

## 체크리스트
- [ ] 로컬에서 lint/build 통과 확인
- [ ] 관련 테스트 작성/통과
- [ ] 콘솔/로그에 에러 없음

## 관련 이슈
Closes #123
```

## 규칙

- **최소 1인 이상 승인(Approve)** 후 병합
- 본인이 작성한 PR은 리뷰어가 머지 (팀 정책에 따라 조정 가능)
- 병합 전략은 **Squash and Merge** 권장 (develop 히스토리를 깔끔하게 유지)
- CI(빌드, lint, 테스트)를 통과하지 못하면 머지 불가
- 변경 파일이 많거나 리뷰 범위가 넓은 PR은 작은 단위로 분리
